## 二、核心变更详细评审

### 2.1 P1 修复: Model 字段 binding:"required" 移除

**变更前:**
```go
// ChatCompletionsRequest
Model string `json:"model" binding:"required"`
// CompletionsRequest
Model string `json:"model" binding:"required"`
```

**变更后:**
```go
// ChatCompletionsRequest
Model string `json:"model"` // handler 显式校验，返回 missing_model
// CompletionsRequest
Model string `json:"model"` // handler 显式校验，返回 missing_model
```

**原因**: Gin 的 `ShouldBindJSON` 在 handler 逻辑之前执行。有 `binding:"required"` 时，缺少 model 的请求被 Gin 拦截，返回 `invalid_request`；移除后，handler 的 `if req.Model == ""` 检查生效，返回语义更准确的 `missing_model`。

### 2.2 Content 数组格式兼容

```go
func normalizeMessages(msgs []map[string]interface{}) []map[string]string
func extractTextContent(v interface{}) string
```

**逻辑**: 在 handler 入口处将 `[]map[string]interface{}` 转换为 `[]map[string]string`。
- `content` 是 string → 直接透传
- `content` 是 `[]interface{}` → 遍历，提取 `type=="text"` 的块，用 `\n` 拼接
- 其他类型 → `fmt.Sprintf("%v", v)` 兜底

### 2.3 K13 ability_types 后端兼容

```go
func parseAbilityTypes(v interface{}) []string
```

**逻辑**: 接受 string（`"chat,completion"`）或 `[]interface{}`（`["chat","completion"]`），统一转为 `[]string`。空值/nil 默认 `["chat"]`。

**评审项**: 变更是否符合系统架构？是否有层间依赖问题？

**评估**:
- ✅ `normalizeMessages()` 放在 handler 层正确 — 入口转换，adapter 层不受影响
- ✅ `parseAbilityTypes()` 放在 handler 层正确 — HTTP 参数解析职责
- ⚠️ `response.go` 移除 `binding:"required"` 后，Model 校验完全依赖 handler 代码纪律。如果后续新增 handler 端点忘记校验，会静默接受空 model。
- 💡 **建议**: 可以考虑保留 `binding:"required"` 并在 handler 中捕获 Gin 的 binding error，映射为 `missing_model`。但当前方案更简单，且端点数量有限（只有 2 个），可接受。

**结论**: ✅ 通过（有 minor 建议）

### 3.2 开发评审

**评审项**: 代码质量、实现正确性、边界情况覆盖？

**评估**:
- ✅ `normalizeMessages` 处理了所有 content 格式：string、`[]interface{}`、nil、空数组
- ✅ `extractTextContent` 非 text 类型（如 `image_url`）被正确忽略
- ✅ `parseAbilityTypes` 覆盖了 string/数组/nil/空字符串/null 全部分支
- ⚠️ `normalizeMessages` 中非 content 字段使用 `fmt.Sprintf("%v", v)` 转换 — 如果 role 字段是 `interface{}`（理论上不会），会得到带引号的字符串。但 Gin 的 JSON 解析会将其解析为 string，所以实际不会触发。

**结论**: ✅ 通过（2 个 minor 关注点）
